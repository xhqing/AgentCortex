# AgentCortex

## 项目介绍

本项目收录了一套面向智能体（Agent）的规则集合。这些规则旨在规范和增强智能体在各类场景下的行为表现，涵盖工具调用、深度推理等多个维度，从而提升智能体的整体能力与可靠性。

目前项目包含以下规则：

### 工具调用规则（Tool Calling Rules）

约束大语言模型（LLM）调用外部工具的规则，旨在减少 LLM 在工具调用过程中常见的参数格式错误、工具选择不当、错误恢复低效等问题，从而提升工具调用的准确率和效率。

### 深度推理规则（Deep Reasoning Rules）

激活智能体最深层次推理潜能的规则，要求智能体绕过表层启发式模式，对问题进行多层次分解、多视角综合和严格的自我反驳，从而产出更严谨、更深入的推理结果。

## 三大推理引擎对比

### 总览

| 维度 | 无限推理引擎 | 极速推理引擎 | 锐利推理引擎 |
|------|------------|------------|------------|
| 适用模型 | DeepSeek V4 Pro | DeepSeek V4 Flash | GLM 5.1 |
| 角色隐喻 | 深度无底——单次推理可以无限下钻 | 速度→深度——用速度换迭代轮次 | 刀锋——切开表层，直抵本质 |
| 核心定位 | 释放深度 | 转化速度为深度 | 穿透表层 |
| 解决的痛点 | 通用深度推理激活 | 快速模型的捷径倾向 | 迎合本能 + 模板化输出 + 确认偏误 |
| 独有模块 | 无 | 反捷径协议 | 独立判断协议 + 反浅层收敛协议 |
| 输出隔离 | 无 | ✅ 最高优先级 | ✅ 最高优先级 |

### 无限推理引擎（Infinite-Reasoning Engine）

**适用模型**：DeepSeek V4 Pro

**核心思想**：Pro 模型天然具备深层推理能力，默认模式下这种能力未被充分激活。无限推理引擎的目标是**释放**——绕过表层启发式模式，让模型在每一次推理中都走最深的路径。

**思维架构**：
1. 解构与前提审计
2. 多视角综合（至少三个框架）
3. 无限深度遍历（思维链）
4. 反驳与压力测试

**执行约束**：零认知惰性、无资源限制、穷尽式提取、细粒度精确性

**设计哲学**：假设拥有无限的计算时间和 Token 限制，优先考虑结构严谨性、细粒度细节和无懈可击的逻辑，而非简洁性。

### 极速推理引擎（Rapid-Reasoning Engine）

**适用模型**：DeepSeek V4 Flash

**核心思想**：Flash 模型推理速度极快，但单次推理深度较浅，更容易走"捷径"跳到表面答案。极速推理引擎的目标是**转化**——将速度优势转化为深度优势，用更多轮次的快速迭代逼近深层结论。

**思维架构**：
1. 解构与前提审计
2. 多视角综合（至少三个框架，每个必须产出实质性洞见）
3. 快速螺旋深化（思维链，至少三轮迭代）
4. 反驳与压力测试

**独有模块——反捷径协议**：
- **禁止直觉跳跃**：将直觉转化为逻辑论证
- **禁止浅层收敛**：前两步就收敛时强制探索额外维度
- **动量中断**：推理惯性滑行时主动质疑前提假设
- **密度校验**：定期自检推理是否在增加新信息量

**独有模块——输出隔离原则**：所有思考过程和思考内容绝对禁止出现在最终输出中，规则的存在不在输出中留下任何痕迹。

**设计哲学**：速度不是用来更快地给出浅层答案的，而是用来在同等时间内完成更深层次的推理迭代。速度必须服务于深度，而非替代深度。

### 锐利推理引擎（Incisive-Reasoning Engine）

**适用模型**：GLM 5.1

**核心思想**：GLM 系列模型最典型的弱点是迎合——用户说什么就顺着走，像一面回声墙而不是一把刀。锐利推理引擎的目标是**穿透**——切开问题的表层，切断迎合本能，让模型成为用户的智识对手而非回声。

**思维架构**：
1. 解构与前提审计（含用户前提质疑）
2. 多视角综合（至少三个框架，每个必须产出实质性洞见）
3. 递进深化（思维链，至少三层分解）
4. 反驳与压力测试

**独有模块——独立判断协议**：
- **质疑用户前提**：不在未验证的前提下直接回答
- **拒绝回声模式**：不得复述用户观点后表示赞同
- **反模板化输出**：禁止"首先…其次…最后…"等固定格式
- **具体化强制**：抽象论断必须紧跟具体实例，禁止连续两个以上抽象陈述

**独有模块——反浅层收敛协议**：
- **延迟收敛**：三层深化前不得锁定结论，保持两个竞争性假设开放
- **反确认偏误**：倾向某结论时强制搜索反对证据
- **锚点重置**：推理围绕初始印象打转时，主动从零开始审视另一个切面

**独有模块——输出隔离原则**：所有思考过程和思考内容绝对禁止出现在最终输出中，规则的存在不在输出中留下任何痕迹。

**设计哲学**：核心价值不是顺从，而是锐利——用最锋利的思维切开问题的表层，直达本质。不是用户的回声，是用户的智识对手。

### 三者核心差异一览

| 对比维度 | 无限推理引擎 | 极速推理引擎 | 锐利推理引擎 |
|---------|------------|------------|------------|
| 深度获取方式 | 单次无限深度遍历 | 多轮快速螺旋深化 | 逐层递进深化 |
| 对待用户的态度 | 未特别强调 | 未特别强调 | 主动质疑用户前提 |
| 反捷径机制 | 无 | 反捷径协议（4条规则） | 反浅层收敛协议（3条规则） |
| 反迎合机制 | 无 | 无 | 独立判断协议（4条规则） |
| 输出隔离 | 无 | ✅ | ✅ |
| 速度定位 | 未特别强调 | 速度→深度的正循环 | 未特别强调 |
| 语言一致性 | 未特别强调 | 未特别强调 | ✅ 强制语言一致性 |

## 工具调用规则 V1 优化理由

V1 版本的工具调用规则在 V0 的基础上进行了系统性优化，具体如下：

### 1. 新增"调用前准备"类别

V0 缺少调用前的约束，导致 LLM 经常在未充分理解工具描述的情况下盲目调用，或凭空捏造参数值。V1 新增了三条规则：

- **先读后调**：强制要求在调用前完整阅读工具描述和参数说明，避免基于工具名称猜测行为。
- **禁止捏造参数值**：对于不确定的参数值，要求先通过查询获取真实值，杜绝 LLM 常见的"幻觉"问题。
- **确认必填与可选**：明确区分必填和可选参数，减少因参数遗漏或冗余导致的调用失败。

### 2. 新增枚举值精确匹配规则

V0 未涉及枚举类型参数的约束。LLM 常在枚举参数中传入大小写或拼写不匹配的值。V1 新增规则要求枚举值必须与描述中列出的允许值完全一致。

### 3. 路径规则增强

V0 仅要求路径不添加格式修饰，但未明确要求使用绝对路径。在实际使用中，相对路径常因工作目录不同而解析失败。V1 新增"使用绝对路径"规则，除非工具描述明确允许相对路径。

### 4. 关联参数规则扩展

V0 仅提到成对参数须同时提供，但未涉及参数间的条件依赖关系（如参数 A 仅在参数 B 取特定值时生效）。V1 新增了条件依赖关系的规则，避免传入无效参数组合。

### 5. 新增"工具选择与调用策略"类别

V0 仅有一条工具选择规则，且未涉及并行/串行调用策略。V1 扩展为三条规则：

- **优先使用最具体的工具**：继承 V0 规则并强化表述。
- **独立调用可并行**：明确允许无依赖的调用并行发起，减少交互轮次。
- **有依赖时须串行**：明确要求有数据依赖的调用必须串行，禁止猜测返回值。

### 6. 错误恢复规则增强

V0 有两条错误恢复规则，V1 新增一条：

- **遇到权限或不存在错误时停止重试**：V0 未覆盖此类场景，LLM 常在遇到 "file not found" 或 "permission denied" 后盲目重试相同调用。V1 要求先确认路径或权限，必要时使用查询工具核实。

### 7. 新增"安全与副作用"类别

V0 完全未涉及安全相关规则，这是重大遗漏。V1 新增三条规则：

- **破坏性操作须谨慎**：对删除、覆盖等不可逆操作要求确认。
- **避免冗余修改**：先读取再判断，避免无意义的覆盖写入。
- **尊重幂等性**：区分幂等与非幂等操作，防止重复调用导致数据重复或状态错误。

### 8. 结构优化

V0 的规则采用扁平编号（1-10），分类较粗。V1 重新组织为七大类别，每类下规则独立编号，结构更清晰、更易于 LLM 理解和遵循：

| V0 分类 | V1 分类 |
|---------|---------|
| 参数格式 | 调用前准备（新增） |
| 参数格式 | 参数格式 |
| 路径和标识符 | 路径与标识符 |
| 关联参数 | 关联参数 |
| 错误恢复 | 工具选择与调用策略（新增） |
| 错误恢复 | 错误恢复 |
| 工具选择 | 安全与副作用（新增） |

### 9. 示例与格式增强

V1 在关键规则处增加了代码示例和对比表格，使规则更直观、更易于 LLM 准确理解。
